Django
Capítulo 4 - Área Administrativa
Como vimos anteriormente, o Django nos proporciona uma interface administrativa,
onde é possível gerenciarmos os dados que serão armazenados em nosso banco.
Inicialmente, o admin pode parecer muito vazio, apenas mostrando os dados através
de CRUDs (CREATE, READ, UPDATE e DELETE), mas existem diversas outras coisas que
podemos fazer no painel administrativo, como filtros, pesquisas e emissão de relatórios.
Veremos como personalizar nosso painel admin ou, como é chamado no Django, nossa
model admin para que ela possa ser bem mais do que um painel, no qual vamos inserir
e gerenciar dados do nosso sistema. A seguir veremos apenas alguns deles.

Django
Capítulo 4 - Área Administrativa
Por agora iremos no arquivo loja/admin.py e iremos criar uma uma classe que servirá
para alterar aparência e comportamento do nosso admin, por isso essa classe que
criaremos herdara de outra, chamada ModelAdmin, para implementar essas
mudanças. No caso, iremos adicionar um filtro com base na data de criação para
nosso model Fabricante. Para isso, criaremos uma nova classe e colocaremos nela uma
variável(componente) " date_hierarchy = 'criado_em' " onde o "criado_em" precisa ser
um campo DataField. Essa classe deve ser posicionada antes de implementar nossos
models no painel do admin, ou seja, antes dos comandos admin.site.register(Model):
class FabricanteAdmin(admin.ModelAdmin):
# Cria um filtro de hierarquia com datas
date_hierarchy = 'criado_em'

Django
Capítulo 4 - Área Administrativa
após adicionar essa classe, para de fato implementarmos filtro ser adicionado no site
admin, precisamos adicionar essa classe como outro parâmetro na linha que possui o
comando de registrar o nosso model de Fabricante na interface do
admin("admin.site.register(Fabricante)"): assim:
admin.site.register(Fabricante,FabricanteAdmin)

Django

Mapeamento objeto-relacional (Object-relational mapping - ORM) é uma técnica para
aproximar o paradigma de desenvolvimento de aplicações orientadas a objetos do
paradigma do banco de dados relacional(tabelas). Tem sido muito utilizada
atualmente e pode trazer muitas vantagens para quem a implementa, tais como: fácil
reutilização do código, manutenibilidade e legibilidade da estrutura da aplicação.

para que ele se comporte da forma adequada em uma estrutura de banco de dados
relacional. Criaremos nossas views e nelas implementamos uma série de métodos para

save_user_usuario: salva qualquer alteração no perfil automaticamente quando
entramos no painel de perfil e alteramos qualquer dado.
